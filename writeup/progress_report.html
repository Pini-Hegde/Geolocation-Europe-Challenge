1. Problem statement

Given a 512×512 street-level photograph taken in one of 12 European countries (Belarus, Finland, France, Germany, Iceland, Italy, Norway, Poland, Spain, Sweden, Turkey, United Kingdom), predict the GPS coordinate (lat, lng) at which it was taken.

Test data2,400 unlabelled "holdout" images — we submit predictions.csv
MetricMedian haversine distance (km) to the true coordinate over the 2,400 test images. Lower is better. Mean distance is the tie-break. Reported secondary rates: <200 km ("got the city"), <750 km ("got the country").
Hard constraints(1) submitted model ≤ 5,000,000 parameters (pretrained weights count); (2) train only on the provided images — no external datasets, no scraped or generated data.

3. The model architecture

A retrieval-augmented hierarchical classifier, evolved over the project. Current form:

  • Backbone: ImageNet-pretrained EfficientNet-B0 (efficientnet_b0.ra4_e3600_r224_in1k, via timm). ~4.0M of the 5.0M parameter budget. Not frozen (all params counted).
  • Multi-view input: 5 crops per image (1 global + 4 corner detail crops) through the shared backbone, then fused.
  • Heads on the fused feature: (a) 12-way country classifier; (b) K = 4 independent geo-cell classifiers — four separately-seeded recursive partitions of the training points, each cell belonging to exactly one country ("CPlaNet" combinatorial partitioning); (c) a within-cell offset regressor; (d) a 224-d L2-normalised embedding.
  • Inference decode: score every labelled training image by log P(country) + meanₕ log P(cellₖ | country) + w · cosine-similarity(embedding), then output a density-weighted spherical mean over the strongest coherent geographic cluster among the top candidates (mode-seeking retrieval).
  • Training losses: haversine-smoothed cell cross-entropy + country CE + offset Huber + a geo-distance-matching loss on the embedding + a 5-view consistency loss + a supervised geographic contrastive loss.

5. Diagnosis — what is limiting us

5.1  The gap is within-country precision, not country classification

The overall median sits exactly at the boundary between the 7 "easy" countries (all < 120 km) and the 5 "hard" continental ones. Crucially, for the easy countries the model already beats the "know the country perfectly" oracle (e.g. Iceland 59 km vs a 178 km country-centroid oracle) — the cell system works well when the country is right. For France the model is worse than the country-centroid oracle (373 vs 330): it is predicting the wrong country outright (~42% of French images land > 500 km, mostly labelled Germany/Italy/Poland).

Every time we halve the cell, the best possible result improves, but the classifier gets the cell right far less often (fewer training images per class, a harder problem). The haversine label smoothing recovers most of the median (because the soft distribution is still roughly in the right place) but not the top-1 accuracy — so few predictions land inside a tight cell, hence few <200 km hits. This is the mechanism behind our 59% vs #1's 65%.

5.3  The hard core: featureless rural continental Europe

The error mass is ~500 validation images where the cell classifier has almost no confidence (top probability ~15%). These are generic rural roads in France / Germany / Poland where a single street-level frame genuinely looks the same across borders. For these images only the embedding provides signal, and the geo-distance / contrastive losses have little to grab onto in a featureless scene. This is a shared ceiling — the whole leaderboard is at ~82% correct-country — but #1 clearly extracts some extra signal (road markings, utility poles, vegetation, sky/light) that our model at 288 px is not learning.

5.4  The 5,000,000-parameter budget

EfficientNet-B0's trunk alone is ~4.0M, leaving only ~1M for all the classification heads — and classification capacity is exactly the bottleneck. A smaller backbone with much larger heads (or a genuinely stronger sub-5M feature extractor) is an open, higher-risk lever.

6. Constraints and lessons

  • Single model required. The clarifications say "submit a single final model", and every leaderboard entry is one model ≤ 5M params. Our best result (122 km) is a 4-model ensemble, likely non-compliant. Mitigation in progress: a model soup (weight-average of same-architecture seeds) — one model, ensemble-like robustness.
  • The holdout is spatially separated from training (verified via retrieval-similarity distributions). No nearest-neighbour shortcut. CV is a faithful proxy.
  • Cross-validation is trustworthy: fold medians 137.2 / 135.3 / 138.0 for the same recipe; old submission CV 150.6 → holdout 139.8.
  • Process lessons: never bundle >1 change per screen; label smoothing must be trained from scratch (not fine-tuned in); EMA decay ≥ 0.999 makes early evaluations meaningless; the smoothing temperature τ must be scaled to the inter-cell spacing.

7. Current plan to close the gap

Three compounding levers, all aimed at cell accuracy at fine granularity (the §5.2 problem):

  1. Coherent k-means cells (E7, running) — compact blobs classify better than kd-tree strips; oracle 33 → 25 km.
  2. Nested country → region → cell hierarchy (E8, queued) — three easy decisions instead of one impossible 1-of-368; a wrong cell still lands in the right region.
  3. Test-time augmentation (flip + multi-scale + native-resolution corner crops) and a longer / EMA-tuned schedule — reliable few-km gains, cheap.

Realistic projection: 122 → ~95–105 km (roughly rank #3). Reaching #1's 47 km likely also needs semantic cells and a training regime found through many submission iterations, and possibly a different backbone.
