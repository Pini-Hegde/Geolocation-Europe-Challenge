## 1. Retrieval / nearest-neighbour inference and the 5M-parameter budget

**Date:** 2026-08-31
**Raised with:** Challenge organisers (TA)

### Our doubt

Our best method (59.22 km CV median) is a pure retrieval approach. At inference it:

1. Runs each image through a ≤5M-parameter backbone to produce a 192-d embedding.
2. Embeds the entire labelled training set into a "gallery" of 192-d vectors, each stored
   with its known (lat, lng).
3. For a query image, finds the nearest gallery vectors and reads the coordinate off the
   neighbours. There is no coordinate regression anywhere.

The backbone itself is 4,959,217 parameters — under the 5,000,000 limit. But the method also
needs the gallery (11,758 × 192 ≈ 2.26M floating-point numbers) shipped alongside it, and the
model produces nothing usable without it.

Two open questions:

1. **Do the precomputed gallery embeddings count toward the 5,000,000-parameter budget?**
   If they count as model state: 4.96M + 2.26M ≈ 7.2M, over budget. If they count as data
   (a deterministic function of the provided training set, which everyone may keep), only the
   4.96M backbone counts and the method is compliant.
2. **Is a retrieval / lookup inference path acceptable at all**, or do the organisers expect a
   model that outputs a coordinate directly from the image?

### Organiser reply (Jan)

> No, the precomputed gallery embeddings do not count toward the 5,000,000-parameter limit.
>
> Only the parameters of the neural network producing the embeddings count toward the limit,
> including any frozen parameters. Stored embeddings, training images, and other cached data
> are considered data/model memory rather than model parameters.
>
> So, as a rule of thumb: count the parameters of the model architecture, not the data stored
> or processed by the nearest-neighbour/retrieval component.
>
> A retrieval or nearest-neighbour approach as you describe is acceptable, provided that you
> only use the permitted training data and models. In particular, the embeddings should be
> generated by a model that is part of your own pipeline. Please do not generate them through
> an external API call, such as an OpenAI embedding API or another hosted embedding service.
>
> Best regards,
> Jan
